## 1. Вход по телефону (OTP: WhatsApp → SMS) [AB]

**Что:** ТЗ 4.1, логика 4.1, интеграции 10.3.

**[A] Чем:**
- Генерация: `secrets.randbelow(10000)` → 4 цифры с ведущими нулями.
- Хранение кода: **Redis, не таблица** (правка к схеме: `otp_codes` из БД убираем): ключ `otp:{phone}` → hash `{code_hmac, attempts}`, TTL 300 с. Сравнение — `hmac.compare_digest(HMAC_SHA256(code, OTP_SECRET))`. Rate-limit ключи там же (`otp:req:{phone}` 3/час, `otp:req:ip:{ip}` 10/час).
- Телефоны: библиотека `phonenumbers`, регион KZ, храним строго E.164.
- JWT: **PyJWT** (не python-jose — у того история CVE), access HS256 30 мин с `sub`, `role`. Refresh — **не JWT, а opaque-токен**: 64 hex из `secrets.token_hex(32)`, в БД `refresh_tokens(user_id, token_hash, expires_at, revoked_at)` — отзыв и ротация тривиальны (правка к схеме: + таблица `refresh_tokens`).
- Каналы: интерфейс `OtpChannel`; SMS — **Mobizon** (простой HTTP API, ориентирован на РК; при регистрации сравнить цену за SMS со SMSC и взять дешевле — API у обоих одинаково примитивный). WhatsApp — BSP c auth-шаблоном (360dialog / Wazzup24), за фича-флагом `otp_whatsapp_enabled`, до одобрения WABA не блокирует ничего.
- **Тестовый номер для ревью сторов (обязателен):** Apple/Google попросят демо-доступ. В `settings` — whitelist: `+77000000000` → код всегда `0000`, SMS не отправляется. Работает и на проде.

**[B] Чем:**
- Экран номера: `TextField` + `mask_text_input_formatter` (`+7 (###) ###-##-##`), сабмит активен при полном номере.
- Экран кода: пакет **`pinput`** (4 ячейки, автофокус, автосабмит на последней цифре), таймер повторной отправки 60 с из `retry_after`, текст «Код отправлен в WhatsApp/по SMS» из поля `channel` ответа.
- Android SMS-автоподстановка: `sms_autofill` (SMS Retriever) — nice-to-have, не блокер.
- Токены: `flutter_secure_storage`. Dio-интерцептор: на 401 → refresh → повтор запроса; **refresh single-flight** (одна «летящая» операция, остальные ждут Completer — иначе шторм рефрешей); refresh упал → чистим токены, состояние «гость».
- Состояние авторизации: Riverpod `AsyncNotifier<AuthState>` (guest / authed(user)); гейт на checkout/профиль — редирект в auth-флоу с возвратом назад (go_router redirect).

**Грабли:** код никогда не пишем в логи; attempts инкрементим атомарно (`HINCRBY`); удаление ключа после успеха; на iOS клавиатура `.number`.

**Готово когда:** новый номер проходит цикл регистрация→выход→вход; 4-я попытка кода — отказ; 6-й запрос кода за час — 429 с таймером в UI; протухший access прозрачно рефрешится посреди скролла каталога; тест-номер работает без SMS.

## 3. Поиск и подсказки [AB]

**Что:** ТЗ 4.5, логика раздел 5. **Выбор движка:** Postgres FTS + pg_trgm. На 4 000 (и даже 20 000) SKU этого достаточно, минус целый сервис в проде. Критерий переезда на Meilisearch: если после запуска качество/латентность не устроят — он ставится в k3s за день и индексируется из той же таблицы; в MVP не тащим.

**[A] Как:**
- Расширения: `CREATE EXTENSION pg_trgm; CREATE EXTENSION unaccent;`
- Колонка: `tsv tsvector GENERATED ALWAYS AS (to_tsvector('russian', coalesce(name,'') || ' ' || coalesce(description,''))) STORED` + `GIN(tsv)`; отдельно `GIN (name gin_trgm_ops)`, `GIN (sku gin_trgm_ops)`.
- Запрос (суть):

```sql
SELECT *, ts_rank(tsv, q) AS r, word_similarity(:s, name) AS sim
FROM products, websearch_to_tsquery('russian', :s) q
WHERE is_active AND (tsv @@ q OR word_similarity(:s, name) > 0.3 OR sku ILIKE :s || '%')
ORDER BY (stock = 0), r DESC, sim DESC
```

- FTS покрывает морфологию («ручки синие» найдёт «ручка шариковая синяя»), trgm — опечатки («тетрад» → «тетрадь»). Транслит/раскладку в MVP не делаем.
- Suggest: таблица `search_queries(query PK, cnt)` — upsert на каждый непустой поиск; выдача: топ-5 `WHERE query LIKE :prefix || '%' ORDER BY cnt DESC` + топ-5 товаров по `word_similarity`. (Правка к схеме: + `search_queries`.)

**[B]:** отдельный экран поиска: автофокус, debounce 300 мс (`Timer` в контроллере), крестик очистки. До ввода — история (последние 10, `shared_preferences`) и популярные чипы. Результаты — компонент листинга из блока 4. Пусто → «Ничего не нашли» + лента хитов.

**Готово когда:** «крандаш», «тетрад в клетку», точный SKU — находят нужное первой пятёркой; подсказки < 150 мс на staging; история чистится.

## 6. Корзина и серверный пересчёт [AB]

**Что:** ТЗ 4.7, логика раздел 2, эндпоинт `POST /cart/calculate`.

**[B] Хранение — выбор:** `shared_preferences` c JSON-снапшотом. Drift/Hive для списка из максимум пары десятков позиций — избыточная зависимость. Riverpod `Notifier<CartState>`; каждое изменение → запись в prefs с debounce 500 мс; старт приложения → восстановление. Корзина девайсная: переживает логин/логаут (это ок по ТЗ).

**[B] Пересчёт:** любой чих (qty, промокод, бонусы, открытие экрана) → debounce 400 мс → `POST /cart/calculate`; локально меняем только qty (optimistic), **все суммы — строго из ответа**. `price_changed=true` → плашка «Цены обновились»; `items[].qty` меньше запрошенного → снекбар «Осталось N шт»; `unavailable` → позиция серая с причиной и кнопкой удалить.

**[B] Блок итогов:** товары / скидка по промокоду / списано бонусами / доставка / итого + строка «Начислим X бонусов». Поле промокода с состояниями apply/applied/error (текст из `promo.error_code` → словарь сообщений). Списание бонусов: поле ввода + кнопка «Списать максимум» (из `bonus.max_allowed`).

**[A]:** одна функция `calculate_cart()` (канон раздела 2 логики), цены читаются из БД, не из кэша. Юнит-тест канонического примера — обязателен до мержа.

**Готово когда:** убил приложение — корзина на месте; сервер урезал qty — UI показал честно; промокод+бонусы+доставка дают копейка-в-копейку суммы канона.

## 10. Изображения и медиа [A]

**Что:** НФТ раздела 7 ТЗ.

- MinIO в k3s; бакет `media` public-read, наружу — через ingress `cdn.SHOP.kz` c `Cache-Control: public, max-age=31536000, immutable` (ключи уникальные — инвалидация не нужна).
- Пайплайн загрузки (`/admin/uploads`): валидация (jpg/png/webp, ≤ 10 МБ) → Pillow: `ImageOps.exif_transpose`, RGB, resize LANCZOS до 200/500/1200 по длинной стороне, WebP quality 82, EXIF не сохраняем. Ключ `p/{uuid}_{size}.webp`. Синхронно — три размера укладываются в ~секунду; Arq не нужен.

Прогресс и ошибки — в CSV-отчёт. Это свои собственные карточки; параллельно уточнить в кабинете мерчанта, нет ли штатной выгрузки контента.

**Готово когда:** загрузка 5 фото в форме товара < 10 с; листинг тянет только 500px-версии (проверить в devtools/чарльзе); повторная загрузка того же файла не ломает ничего.

## 11. XLSX-импорт и массовые операции [A]

**Что:** ТЗ 6.3, логика §4.7. Критичный модуль — через него заезжают все 4000 позиций.

- Чтение: `openpyxl` `load_workbook(read_only=True)`, `iter_rows(values_only=True)` — файл на 10к строк не съест память.
- Two-pass: (1) полная валидация всех строк → отчёт (dry-run на этом останавливается); (2) запись чанками по 500 в транзакциях, upsert по SKU (`INSERT … ON CONFLICT (sku) DO UPDATE`), поля `images`/`stock_source=manual`-остатки не трогаем.
- `category_path` — сплит по ` / `, поиск в предзагруженном дереве; неизвестная категория = ошибка строки (категории импортом не создаём — осознанно, чтобы опечатка не плодила мусорные ветки).
- `attr:*` колонки → JSONB + `attr_order`. Экспорт — `write_only` workbook, тот же порядок колонок.
- Накладная по заказу (`/admin/orders/{id}/invoice`) — перенести существующий openpyxl-пайплайн З-2: функция принимает order + items-снапшоты, отдаёт `BytesIO` стримом.

**Готово когда:** пункт 8 чек-листа приёмки (4000 строк, dry-run с ошибками, импорт < 2 мин) + повторный импорт того же файла = 0 created, N updated, ничего не сломано.

## 13. Админ-панель [A]

**Что:** ТЗ раздел 6.

**Стек и почему:**
- **Vite + React 18 + TypeScript** — Claude генерит это быстрее и чище всего.
- **shadcn/ui** — таблицы, формы, диалоги, тосты (`sonner`) из коробки, без дизайнера.
- **TanStack Query** — кэш, инвалидация по мутациям, состояния загрузки.
- **TanStack Table** — таблицы товаров/заказов (сортировка, колонки).
- **react-hook-form + zod** — формы товара/промокода/настроек с валидацией.
- **react-router v7** — роутинг по модулям.
- **openapi-typescript** — типы генерятся из `openapi.yaml`: админка типобезопасно прибита к контракту, расхождение ловится на компиляции.

**Структура:** `src/features/{products,orders,categories,promos,bonuses,banners,users,settings,dashboard}/` — страница + компоненты + api-хуки рядом. Общий `api/client.ts` (fetch + токен + 401-редирект на логин).

**Auth:** access-JWT в памяти (zustand), refresh — как в приложении. Админка живёт за IP-allowlist на ingress (риск XSS-кражи токена принят осознанно и компенсирован сетевым периметром).

**Ключевые экраны, на которые потратить время:** импорт (drag-n-drop файла → таблица отчёта dry-run с фильтром «только ошибки» → кнопка «Применить»), заказ (смена статуса селектом с подтверждением, для kazpost — обязательное поле трека), товар (динамические строки характеристик, сортировка фото перетаскиванием).

**Готово когда:** пункты 8–11 чек-листа приёмки ТЗ проходят силами менеджера без разработчика рядом.

## 15. Инфраструктура, CI, окружения [A]

**Что:** НФТ ТЗ §7, стек §9.

- **Окружения:** staging — текущий VPS (Contabo, k3s), prod — **PS.kz** (ПДн в РК): отдельный k3s, отдельный kubeconfig-контекст. Никаких общих БД/бакетов между окружениями.
- **Манифесты:** `deploy/` в backend-репо, kustomize `base` + overlays `staging|prod`. Секреты — k8s Secrets, заведённые руками по документированному списку `deploy/SECRETS.md` (какие ключи нужны, без значений). Ingress-nginx + cert-manager (letsencrypt), админка и `/admin/*` API — allowlist IP.
- **CI (GitLab):** backend: `ruff` → `pytest` (поднимая Postgres/Redis сервисами) → kaniko build → auto-deploy staging из `main`; тег `v*` → deploy prod с manual gate. Mobile: `flutter analyze` → tests → apk-артефакт на MR; тег → сборка релизных apk/aab + ipa (мак-раннер или локально у Трека B — решить по факту наличия мака в CI).
- **Бэкапы:** CronJob `pg_dump | gzip` → бакет на PS.kz S3, хранение 30 дней; **восстановление отрепетировать на staging до релиза** (пункт 14 приёмки).
- **Фоновые:** Arq-воркер отдельным Deployment; кроны — в нём же (`cron_jobs` арки), не в k8s CronJob — меньше сущностей.

**Готово когда:** пуш в main доезжает до staging без рук за < 10 мин; тег поднимает прод; рестор бэкапа проверен.
